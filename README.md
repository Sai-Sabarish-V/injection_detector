# SQL Injection Detector

A machine-learning-based SQL Injection (SQLi) detection system that classifies SQL queries as either **Safe** or **SQL Injection**.

The project uses TF-IDF-based text representations, manually extracted SQL features, Logistic Regression, XGBoost, and an ensemble-based prediction approach. The trained models and preprocessing components are saved using Joblib and can then be used by the command-line detector.

---

## Features

* Character-level TF-IDF features
* Word-level TF-IDF features
* Hand-crafted SQL query features
* Logistic Regression classifier
* XGBoost classifier
* Ensemble-based detection
* SQL Injection probability scoring
* Oracle Database integration
* Interactive command-line SQL query interface

# 5. Configure Oracle Database

The detector uses Oracle Database to execute queries that are classified as safe.

Open:

```text
database/oracle.py
```

The Oracle connection is created using a username, password, and DSN.

You can configure your Oracle credentials in the project where the `OracleDatabase` object is initialized.

For example:

```python
db = OracleDatabase(
    user="YOUR_USERNAME",
    password="YOUR_PASSWORD",
    dsn="localhost:1521/XEPDB1"
)
```

Replace:

```text
YOUR_USERNAME
YOUR_PASSWORD
```

with your Oracle credentials.

For example:

```python
db = OracleDatabase(
    user="system",
    password="your_password",
    dsn="localhost:1521/XEPDB1"
)
```

**Do not commit real database passwords to GitHub.**

For a public repository, environment variables are recommended instead.

# 6. Run the Detector

After:

* installing the dependencies,
* placing the dataset in the correct location,
* running `main.ipynb`,
* generating the `.pkl` files,
* and configuring Oracle,

run:

```bash
python detector.py
```

The detector loads the trained models and vectorizers from the `models pkl files` directory.

You will be prompted to choose the model:

```text
Use XGBoost model? (y/n):
```

Then enter a SQL query.

Example:

```text
SQL> SELECT * FROM employees WHERE employee_id = 101;
```

The detector returns the classification and probability:

```text
Detector: Safe (95.21%)
```

If a potential SQL Injection is detected:

```text
Detector: SQL Injection (99.87%)
BLOCKED: Potential SQL injection detected.
```

Queries classified as safe are passed to the Oracle database for execution.

# How It Works

The detection pipeline consists of several stages.

```text
                  SQL Query
                      │
                      ▼
             ┌─────────────────┐
             │ Feature         │
             │ Extraction      │
             └────────┬────────┘
                      │
          ┌───────────┴───────────┐
          ▼                       ▼
   Character TF-IDF          Word TF-IDF
          │                       │
          └───────────┬───────────┘
                      ▼
             Combined Features
                      │
                      ▼
          Hand-crafted SQL Features
                      │
                      ▼
               Feature Scaling
                      │
                      ▼
             ┌─────────────────┐
             │ ML Classifiers  │
             │                 │
             │ Logistic Reg.   │
             │ XGBoost         │
             └────────┬────────┘
                      │
                      ▼
                Prediction
                      │
             ┌────────┴────────┐
             ▼                 ▼
           Safe           SQL Injection
             │
             ▼
       Oracle Database
```

The feature-engineered Logistic Regression model uses character and word TF-IDF features together with manually extracted SQL features. The notebook also trains an XGBoost model on the final feature representation.

---

# SQL Feature Engineering

The system extracts features including:

* Query length
* Word count
* Single and double quotes
* Backticks
* Semicolons
* Equals signs
* Parentheses
* Commas
* SQL operators such as `AND` and `OR`
* SQL keywords such as `SELECT`, `UNION`, `INSERT`, `UPDATE`, `DELETE`, and `DROP`
* SQL comments
* Hexadecimal expressions
* `SLEEP`
* `BENCHMARK`
* `xp_cmdshell`
* Statement count
* Quote/comment patterns
* Tautological expressions

These features are combined with TF-IDF representations before classification.

---

# Oracle Integration

The Oracle database wrapper uses the `oracledb` Python package.

The database class:

1. Establishes an Oracle connection.
2. Receives the query from the detector.
3. Removes a trailing SQL*Plus-style semicolon.
4. Executes the query.
5. Returns rows for queries that produce results.
6. Commits the transaction.
7. Closes the cursor and connection when finished.

The detector blocks queries classified as SQL Injection before they reach the database.

Run:

```text
main.ipynb
```

The generated `.pkl` files must remain in:


because `detector.py` loads them from that directory.
